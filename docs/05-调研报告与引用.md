# 从零手写 Agent（五）：调研报告、引用与落盘——Loop 仍不变

第四篇之后，我手里已经有一个 **能上网查资料** 的 Agent：`search_web`、`fetch_url` 和 calculator 挂在同一个 `_agent_loop` 里，`-v --trace` 也能把整条轨迹翻出来。  
真正卡人的，是另一类问题——用户说：「帮我 **调研** 一下，写 **Markdown 报告**，**保存到** `reports/xxx.md`。」

终端里一段口语摘要，对「Python 几号发布」也许够用；对「整理一份可转发、带出处、能落盘」的简报，就不算 **交付**。  
第五篇记录的是：在 **Loop 伪代码不动** 的前提下，我如何补上 **交付层**——报告长什么样、文件怎么写进去、以及踩过的坑：**Tool 明明注册了，磁盘上却没有文件**。

---

## 1. 第四篇之后，差的那一层是什么？

第四篇 §7 把边界说清楚了：当前形态是 **Web 调研原型**——能搜、能抓、能多步推理；离「行业调研产品」还远。  
和 **本篇** 直接相关的缺口，其实就三件事：

**结构化正文。** 摘要、分节、局限、参考文献，而不是聊天里的散文。  
**可核对的引用。** 正文里的链接最好来自本轮 `search_web` / `fetch_url` 的 Observation，而不是模型「记得」的 URL。  
**持久文件。** 用户点名 `reports/foo.md` 时，应该能在项目里 `cat` 到文件——不是「我把 Markdown 贴在回复里，您自己存一下」。

**注意：** 这不是再注册五个搜索 Tool。交付靠的是 **输出契约 +（可选）来源状态 + 一个写文件 Tool**。  
第四篇已经解决 **搜集**；本篇先解决 **落盘**，引用状态（`sources`）作为下一步在 state 里记账——思路写在 §4，代码还可以后补。

商用调研 Agent 在报告上通常还多一层 **规划与验收**（大纲、交叉验证、失败可测）。学习版刻意先走最小路径：**Markdown + `save_markdown`**，和第四篇的「Loop 不变，只加 Tool」同一哲学。

---

## 2. 踩坑实录：「保存到 reports/」与「真的保存了」不是一回事

### 2.1 还没有 save Tool 时

我先用第五篇 §8 里的目标句子跑了一轮（`qwen2.5:3b`，`python main.py -v --trace`）：

```bash
python main.py -v --trace \
  '调研 Python 3.13 相对 3.12 的主要新特性，写 Markdown 报告并保存到 reports/python-313.md'
```

当时 `ALL_TOOLS` 里只有 calculator、search_web、fetch_url。trace 很干脆：`steps=2`，一次 `search_web("Python 3.13 新特性")`，然后模型说搜不到 3.13 和 3.12 的对比，让我去官网，还顺手 offer 一个 **空模板**。  
SERP 也偏：Wikipedia 总论、python.org **首页**、W3Schools 入门——几乎没有 whatsnew；**fetch_url 没出现**。

这里有两层失败叠在一起：**协议上不可能写盘**（没有 save 这种 Action），**搜集也浅**（一次泛 search 就收工）。  
**注意：** 不是「大模型不能创建文件」——LLM 从不直接写磁盘；**落盘必须是 Tool 或 CLI 后处理**。用户写清路径，若 registry 里没有对应 function，任务在设计上就 **完不成**。

### 2.2 补上 save_markdown 之后：Tool 没坏，Loop 却「见字就收工」

我在 `agent/tools/save_markdown.py` 里加了路径沙箱（只允许 `reports/`、禁 `..`），并挂进 `ALL_TOOLS`。直调 Tool 没问题：

```bash
python -c "from agent.tools.save_markdown import save_markdown; print(save_markdown('hello.md', '# test'))"
# → Saved: reports/hello.md
```

若用户 **只** 要求 save、不要 search，3B 也往往会老实地 `tool_call`：

```bash
python main.py -v --trace '请立即调用 save_markdown，filename 为 test.md，content 为 # Hi'
```

但 **同一条「调研 + 报告 + 保存」** 命令，改 prompt 前仍经常失败：模型 search 一两轮后，在 **聊天里** 贴 Markdown，或说「您可以保存到 reports/…」，**最后一轮没有 tool_calls**。  
原因在 Loop 本身：

```text
if not message.tool_calls:
    return 最终答案
```

只要模型 **不再发起 Tool**，Loop 就认为任务结束——**磁盘上可以没有任何文件**。`save_markdown` 一直在 `tools=` 列表里，但 **`tool_choice=auto` 下调不调全看模型**。长报告时，3B 特别爱把 Markdown 当普通回复，甚至把超长 `content` 塞进代码块，而不是放进 Tool 参数。

我在 `agent/prompt.py` 里写了硬约束：用户提到保存 / `reports/*.md` 时 **必须** 调用 `save_markdown`；在 `agent/loop.py` 里加了 **save nudge**（用户意图是落盘且还没有 `Saved:` 时，再塞一条 user 催促）；在 save nudge 的 **下一轮** 用 `agent/llm.py` 的 **`tool_choice=save_markdown`** 逼 Ollama 发起 save。  
换 **7B** 往往比单靠 nudge 更省心——内容质量仍取决于 search/fetch，但至少 **`Saved:`** 可以在 `joyjoy` 和 trace 里 **验收**。

### 2.3 模型问题还是代码问题？

两边都有，**性质不同**。

**模型侧（尤其 3B）：** 上下文一长，更容易「提前收工」——search 完就总结，忘记 save；或不愿把整篇 Markdown 塞进一次 JSON 参数。短命令能 save、长链路漏 save，说明 **能力在，策略差**，不是 Tool 没注册。

**设计侧：** 学习版 Loop 默认 **「最终答案 = 最后一条 assistant 文本」**，没有定义 **「交付 = 出现 Saved:」**。这不是 `save_markdown` 写错了，而是 **完成条件偏松**。商用产品常会拆轮次（搜集轮 / 成稿轮 / 强制 save 轮），或在编排层做后处理落盘。

**注意：** **注册 Tool = 提供能力；调用 Tool = 模型决策；任务算不算完 = Loop 规则。** 三者别混为一谈。我现在的缓解顺序是：**prompt → nudge → 强制 tool_choice → 更大模型**；接下来还计划在 state 里记 **sources**，从 Observation 收紧引用（§4）。

## 3. 报告长什么样：一份最小 Markdown 契约

学习版不必上 PDF。我在 system / 模板里固定 roughly 这样的骨架，让模型填空：

```markdown
# {题目}

> 生成时间：{本地时间} · 模型：{OLLAMA_MODEL}

## 摘要
（3–5 句，只基于下文，不引入未检索事实。）

## 主要发现
### …

## 局限与未覆盖
（search 超时、只读到 snippet、源为英文等如实写。）

## 参考文献
[1] 标题 — URL
```

**注意：** **「局限」** 一节很值钱——Tool 返回 `Error: …` 时写进报告，比假装调研过诚实。摘要尽量 **基于 findings**，否则小模型容易先「发挥」再搜。正文 `[1]` 与文末列表 **编号一致**；第四篇 §4.2 里「权威快报」被改成「权力建报」，就是 **有 Observation 仍会改写** 的提醒——后面要靠 sources 和原文引用收紧。

## 4. 引用从哪来：本轮检索「足迹」（下一步）

聊天里模型可以编造 URL；报告里我希望 **尽量只引用本轮见过的链接**。

打算在 **`AgentState`** 里加轻量 `sources`：每次 `search_web` 返回后，用确定性代码解析 `URL:` 行；`fetch_url` 成功后记下请求的 url 和 snippet。生成报告前，把列表注入 system（不占 Tool 槽）：

```text
【本轮已收集来源，引用仅限下列 URL】
[1] What’s New In Python 3.13 — https://docs.python.org/3/whatsnew/3.13.html
```

这和 RAG 向量库不是一路——只是 **本次 run 的足迹**，可解释、适合手写 Agent。进阶可以对成稿 Markdown 做 URL 白名单校验；Agent 层无法 100% 杜绝幻觉，只能 **缩小面 + 可测**。

hook 可以挂在 `loop` 里 append tool 结果之后，或包一层 `execute_tool`；**Loop 结构不用改**。

---

## 5. 落盘：`save_markdown` 这个 Tool

实现方式和 calculator 一样：`Tool(name, schema, fn)`，在 `agent/tools/save_markdown.py`。

模型侧看到两个参数：**`filename`**（`python-313.md` 或 `reports/python-313.md` 均可，解析后都落在 `REPORTS_DIR`，默认 `reports/`）和 **`content`**（完整 Markdown 字符串）。成功返回 `Saved: reports/…`；失败返回 `Error: …` 字符串，Loop 照常把 Observation 塞回 messages。

路径上我做了学习版该有的限制：禁止 `..` 和绝对路径，单文件大小受 `SAVE_MARKDOWN_MAX_BYTES` 约束。生成的 `reports/*.md` **gitignore**，目录用 `reports/.gitkeep` 占位——报告是运行产物，不是仓库源码。

一条理想轨迹仍然和第四篇衔接：

```text
user：调研 … 保存到 reports/python-313.md
→ search_web / fetch_url（官方 whatsnew、release）
→ save_markdown(filename, content)
→ tool：Saved: reports/python-313.md
→ assistant：告知路径
```

也可以不新增 Tool、用 shell 重定向最后一轮输出——但 **显式 save** 更贴近「Agent 交付」，以后也好加「没有 Saved: 不算完」的终止条件。

---

## 6. Prompt 与第四篇规则并存

`agent/prompt.py` 在第四篇互斥说明之上，加了 **报告 / save** 一条线：用户说「报告、调研、保存 md」时，先 search/fetch，再成稿，**最后 save_markdown**；禁止只给模板或「您可以自行保存」。  
第四篇的「闲聊直答、算式用 calculator、有 URL 用 fetch」仍然有效——多 Tool 靠 **description + system** 分工，小模型仍会错，靠 trace 调。

以后若想再进一步，可以试 **轻量 Plan**：第一轮只出大纲 JSON，代码解析后再进 Loop——和笔记里 Planning 章节同源，等 sources 跑通再加，避免一次堆太多状态。

## 7. 本地怎么试

**只测写文件：**

```bash
python -c "from agent.tools.save_markdown import save_markdown; print(save_markdown('hello.md', '# test\n\nbody'))"
cat reports/hello.md
```

**走完整 Agent（出网 + 模型多步，建议 prompt 写清 search → fetch → save）：**

```bash
python main.py -v --trace \
  '调研 Python 3.13 相对 3.12 的主要新特性：先 search 再 fetch 官方 whatsnew/release，写 Markdown（摘要、主要发现、局限、参考文献），最后 save_markdown 保存到 python-313.md'

ls reports/
head -40 reports/python-313.md
```

trace 里若出现 `save_markdown` 且 tool 返回 **`Saved:`**，说明 **交付链** 走通；若只有长文字、无 save，回到 §2——多半是 **模型 + 完成条件**，不是 Tool 未注册。仓库默认 **`qwen2.5:7b`**（`config.py` / `.env.example`）；博文 §2 部分踩坑记录仍为 3b 实测。

## 8. 还常会混淆的几点

**没有 save，算不算调研 Agent？**  
第四篇止：**能调研、不能交付**。本篇补的是 **协议上的写盘能力**；内容好不好仍看搜集与模型。

**强制引用后还瞎编怎么办？**  
sources + 事后脚本查 URL 是否 ⊆ 足迹；或换更大模型。报告任务也可以拆成「最后一轮只出 Markdown、再强制 save 一轮」——仍是同一个 Loop，只是轮次语义不同。

**和 Planning 什么关系？**  
大纲 JSON 是轻量 Plan；完整 Plan-and-Execute 适合在 save 与 sources 稳了再加。

---

## 9. 收束

第四篇解决 **能不能上网读材料**；本篇解决 **能不能交一份 md 文件**。Loop 仍是 `prepare_messages → llm → execute_tool → append`；变的是 **`save_markdown`**、prompt、以及为 save 服务的 **nudge / 强制 tool_choice**。  
引用与 `AgentState.sources` 是同一交付故事里的下一块拼图——让 `[1]` 对应真实 Observation，而不是聊天里的「权力建报」。

若你跟着系列写代码：先确认 **`Saved:`** 能在 trace 里出现，再抠报告质量；别和第四篇一样，把「Tool 返回了」当成「用户任务完成了」。
